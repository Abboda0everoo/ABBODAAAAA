# تقرير تنفيذ متطلبات AI Visibility و Technical SEO

مرجع هذا التقرير هو وثيقة «AMPLIQ AI Visibility & Technical SEO — الإصدار 1.0، نوفمبر 2026».
الفرع: `feature/ai-visibility-seo`. الدومين المعتمد: `https://ampliq.netlify.app/`، كما تنص الوثيقة.

---

## 1. تدقيق ما قبل التعديل (البند 2 من الوثيقة)

الموقع مبني كصفحات HTML ثابتة يولّدها `build.mjs` من ملفات JSON في `src/content/`. لوحة التحكم Decap CMS على `/admin/`، والنشر تلقائي على Netlify.

| البند | الحالة قبل التعديل | القرار |
|---|---|---|
| Title وDescription لكل صفحة ولكل لغة | ✅ موجود، ويُعدَّل من اللوحة | أُبقي كما هو |
| H1 واحد في كل صفحة | ✅ يتحقق منه البناء | أُبقي |
| `lang`/`dir` لكل لغة | ✅ | أُبقي، وأُضيف له اختبار |
| Canonical وhreflang متبادل وx-default | ✅ موجود (عند ضبط رابط الموقع) | نُقل إلى وحدة مركزية |
| Open Graph وTwitter Card | ✅ جزئياً (ينقصه twitter:title/description/image وog:image:alt) | استُكمل |
| صور OG مقاس 1200×630 لكل صفحة | ✅ موجودة | أُبقيت |
| Sitemap مع xhtml:link | ✅ موجود، لكن `lastmod` يتغيّر مع كل بناء | **صُحّح** |
| robots.txt | ✅ موجود، لكن لا يسمّي زواحف البحث والذكاء الاصطناعي | **طُوّر** |
| Schema | ✅ Organization وProfessionalService وService وFAQPage وArticle وBreadcrumbList، لكن بلا `@id` ثابت وتتكرر Organization داخل كل كائن | **أُعيد تنظيمه** |
| llms.txt | ❌ غير موجود | **أُضيف** |
| Security Headers | ❌ غير موجودة (فقط noindex للوحة) | **أُضيفت** |
| Cache-Control للملفات الثابتة | ❌ الافتراضي | **أُضيف** |
| أحداث التحليلات | `generate_lead` و`contact_click` | **وُحّدت مع أسماء الوثيقة** |
| التحكم في الفهرسة (noindex) من اللوحة | ❌ | **أُضيف** |
| الكاتب وتاريخ التحديث للمقالات | ❌ | **أُضيفا (اختياريان)** |
| اختبارات الجودة | فحص H1 فقط | **أُضيف `npm test`** |
| الأداء: WebP، lazy loading، WOFF2، `font-display: swap`، أولوية صورة الـ Hero | ✅ موجودة | أُبقيت |
| حماية اللوحة | ✅ الدخول بحساب GitHub عبر OAuth، ولا توجد مفاتيح في ملفات الموقع | تحقق منه اختبار الأسرار |

## 2. ما تم تنفيذه

### البنية التقنية (P0)

**وحدة SEO مركزية: `src/seo.mjs`**
- تولّد لكل صفحة: Title، Description، Robots، Canonical، hreflang، Open Graph، Twitter Card.
- الصفحة المخفية من البحث تأخذ `noindex, follow` بدون Canonical وبدون hreflang، حتى لا تتعارض الإشارات.
- الصفحات العامة تأخذ `index, follow, max-image-preview:large`.

**البيانات المنظمة (JSON-LD)**
- كيان `Organization` واحد بمعرّف ثابت `#organization`، وكيان `WebSite` بمعرّف `#website`. الاثنان متطابقان في كل الصفحات.
- كل Schema آخر يشير إلى المنظمة عبر `@id` بدل تكرار بياناتها، وهذا يشمل: `Service.provider`، و`BlogPosting.publisher`، و`ProfessionalService.parentOrganization`.
- بيانات المنظمة مأخوذة فقط مما يظهر على الموقع:
  - الاسم والشعار والوصف.
  - المدينة (الرياض).
  - الأسواق الأربعة المذكورة في قسم الأرقام: السعودية ومصر والإمارات والعراق.
  - البريد والهاتف.
- المقالات صار نوعها `BlogPosting`، و`dateModified` فيها تاريخ تعديل حقيقي. الكاتب اختياري: إن وُجد يظهر في الصفحة وفي الـ Schema، وإلا يُنسب المقال لـ Ampliq.
- أُضيفت حسابات التواصل الرسمية (Instagram وSnapchat وLinkedIn وX) إلى `sameAs`، وتُعدَّل من اللوحة.
- لم تُضف تقييمات ولا جوائز ولا عنوان تفصيلي غير موثق.

**Sitemap**
- `lastmod` يُحسب من تاريخ آخر تعديل فعلي (من سجل Git) لملفات المحتوى التي تعرضها كل صفحة. إعادة البناء وحدها لا تغيّره.
- الصفحات المخفية من البحث تُستبعد من الخريطة تلقائياً.

**robots.txt**
- يسمح صراحة لهذه الزواحف بالصفحات العامة:
  - Googlebot وBingbot
  - OAI-SearchBot وChatGPT-User
  - PerplexityBot وClaude-SearchBot
- يحظر `/admin/` فقط، ولا يحظر CSS أو JS أو الصور.

**llms.txt**
- يُولَّد تلقائياً من الصفحات المنشورة فعلاً، بالإنجليزية والعربية.
- يحتوي الخدمات وصفحات الشركة والمقالات وبيانات التواصل.
- لا يحتوي روابط وهمية، ويتحقق الاختبار من كل رابط فيه.

### الأمان والأداء (P0)

ملف `netlify.toml`:
- **Security Headers:**
  - `X-Content-Type-Options`
  - `Referrer-Policy`
  - `X-Frame-Options`
  - `Permissions-Policy`
- **Content-Security-Policy:** لم تُضف بعد عمداً، كما توصي الوثيقة، إلى أن تُحصر الخدمات الخارجية (GTM وFormspree واللوحة) وتُختبر.
- **Cache-Control:**
  - ملفات CSS وJS (روابطها تحمل بصمة المحتوى) والخطوط: سنة.
  - الصور: أسبوع، لأنها قد تُستبدل من اللوحة بنفس الاسم.
  - صفحات HTML: تُراجَع في كل زيارة، فيظهر أي تعديل فوراً.

### لوحة التحكم (البند 19)

- خيار **«إخفاء الصفحة من محركات البحث»** في كل صفحة وخدمة ومقال. الصفحة الرئيسية مستثناة حتى لا تُخفى بالخطأ.
- في المقالات ثلاثة حقول جديدة: **اسم الكاتب**، و**صفة الكاتب**، و**تاريخ آخر تحديث للمحتوى**.
- كان موجوداً من قبل: عنوان ووصف SEO مستقلان لكل لغة، وصورة الغلاف، وحالة المسودة.

### التحليلات (البند 14)

أحداث `dataLayer` المتوافقة مع الوثيقة:

| الحدث | متى يُرسل |
|---|---|
| `generate_lead` | إرسال النموذج بنجاح |
| `click_phone` | الضغط على رقم الهاتف |
| `click_email` | الضغط على البريد |
| `click_whatsapp` | الضغط على واتساب |
| `language_switch` | تغيير لغة الموقع |
| `view_service` | مشاهدة صفحة خدمة |

- `page_view` يرسله GTM تلقائياً.
- لا يُرسل أي نص أو بيانات تواصل أدخلها الزائر.
- يُحمَّل GTM فقط بعد موافقة الزائر على الكوكيز، كما كان من قبل.

### الاختبارات (البند 20)

الأمر `npm test` يبني الموقع ثم يشغّل `scripts/check.mjs`.

**يفشل الاختبار عند:**
- رابط داخلي مكسور.
- Canonical مفقود أو مكرر أو لا يشير للصفحة نفسها.
- hreflang غير متبادل أو يشير لصفحة مخفية.
- صفحة عامة غير موجودة في الـ Sitemap، أو صفحة مخفية موجودة فيه.
- JSON-LD غير صالح.
- `lang`/`dir` خاطئ، أو أكثر من H1، أو أكثر من Title.
- robots.txt يحظر الموقع، أو لا يسمّي Googlebot وBingbot وOAI-SearchBot.
- رابط في llms.txt خارج الموقع.
- أي شيء يشبه مفتاح API أو رمز GitHub في الملفات العامة.

**ينبّه فقط (بدون فشل) عند:**
- تكرار العناوين أو الأوصاف.
- عنوان أو وصف أطول أو أقصر من المناسب.

**النتيجة الحالية:** 29 ملف HTML، منها 28 صفحة قابلة للفهرسة. **0 أخطاء** و4 تنبيهات: أوصاف إنجليزية لأربع صفحات طولها بين 171 و180 حرفاً، والأفضل 160 أو أقل، وتُعدَّل من اللوحة:
- `/en/`
- `/en/services/`
- `/en/clients/`
- `/en/services/digital-marketing/`

الوثيقة نفسها تمنع نشر محتوى أو أرقام أو عملاء غير موثقين، لذلك هذه البنود متوقفة على مدخلات منكم:

| البند | المطلوب منكم |
|---|---|
| **القطاعات الأربعة** (Marketing، Technology، Business Solutions، Human Capital) — البند 8 | الموقع حالياً مبني على ثلاث خدمات: التسويق الرقمي، والموارد البشرية، والبرمجة. نحتاج قائمة الخدمات المعتمدة فعلاً تحت كل قطاع ونصوصها. الروابط الحالية ستُحفظ مع تحويلات 301 عند أي تغيير. |
| **دراسات الحالة** — البند 9 | مشاريع موثقة ومصرّح بنشرها: التحدي والحل ودور Ampliq والنتائج. النظام يُبنى عند توفر أول دراسة، حتى لا تُنشر صفحات فارغة. |
| **فريق العمل والأسئلة الشائعة العامة** — البند 16 | أسماء وصفات حقيقية بموافقة أصحابها، وأسئلة حقيقية من العملاء. |
| **كاتب المقالات** — البند 10 | اسم وصفة الكاتب لكل مقال، وتُضاف من اللوحة. |
| **GPTBot** — البند 5 | قرار مستقل: هل تسمحون باستخدام محتوى الموقع في تدريب نماذج OpenAI؟ هو مسموح حالياً بالقاعدة العامة. لا علاقة له بظهوركم في بحث ChatGPT، فذلك يتحكم فيه OAI-SearchBot وهو مسموح صراحة. |
| **GA4 / GTM** — البند 14 | معرّف حاوية GTM (`GTM-XXXXXXX`) يوضع في اللوحة. بعدها تُربط الأحداث أعلاه في GA4. |

| **قياس الظهور في الذكاء الاصطناعي** — البند 14.1 | مجموعة الثلاثين سؤالاً الشهرية والمتابعة الدورية. هذا عمل تشغيلي وليس برمجياً. |
| **قياس Core Web Vitals وLighthouse** | يُقاس على الموقع المنشور عبر PageSpeed Insights بعد الدمج، وتوثَّق النتائج. |

## 4. الملفات التي أُضيفت أو عُدّلت

| الملف | التعديل |
|---|---|
| `src/seo.mjs` (جديد) | وحدة SEO مركزية: وسوم `<head>` وكيانا Organization وWebSite |
| `src/templates/layout.mjs` | يستخدم الوحدة المركزية، ويمرّر نوع الصفحة لأحداث التحليلات |
| `src/templates/pages.mjs` | Schema مربوطة بـ `@id`، و`BlogPosting` مع الكاتب وتاريخ التعديل، وعرض اسم الكاتب في المقال |
| `src/content.mjs` | تواريخ التعديل الحقيقية من Git، وقراءة noindex وحقول الكاتب |
| `build.mjs` | استبعاد الصفحات المخفية، و`lastmod` الحقيقي، وrobots.txt الجديد، وتوليد llms.txt |
| `src/admin/config.mjs` | حقول اللوحة الجديدة (noindex، والكاتب، وتاريخ التحديث) |
| `src/scripts/main.js` | أحداث التحليلات بأسماء الوثيقة |
| `netlify.toml` | Security Headers وCache-Control |
| `scripts/check.mjs` (جديد)، `package.json` | اختبارات الجودة (`npm test`) |
| `README.md`، `DASHBOARD.md`، `docs/SEO-REPORT.md` | التوثيق |

لم يتغيّر أي رابط منشور، ولا التصميم، ولا أي نص ظاهر للزائر. الاستثناء الوحيد: يظهر اسم الكاتب في المقال إذا أُضيف.

## 5. النشر والتراجع

**النشر**
1. راجعوا الفرع `feature/ai-visibility-seo` وادمجوه في `main`.
2. ينشر Netlify تلقائياً خلال دقيقة أو اثنتين.

**بعد النشر**
- في Search Console أعيدوا إرسال `sitemap.xml`.
- افحصوا عينة من الصفحات في Rich Results Test وSchema Markup Validator.
- تأكدوا من فتح هذه الروابط:
  - `https://ampliq.netlify.app/robots.txt`
  - `https://ampliq.netlify.app/llms.txt`
  - `https://ampliq.netlify.app/sitemap.xml`

**التراجع**
- من Netlify: افتحوا **Deploys**، واختاروا النسخة السابقة، ثم **Publish deploy**. يتم ذلك فوراً ودون تعديل الكود.
- أو من GitHub: اعملوا Revert لطلب الدمج.

**ملاحظة:** الظهور في Google أو ChatGPT أو Gemini أو Perplexity نتيجة خارجية لا يضمنها الكود وحده. هذه التعديلات تجعل الموقع قابلاً للاكتشاف والفهم بشكل صحيح، والنتائج تُقاس دورياً.
