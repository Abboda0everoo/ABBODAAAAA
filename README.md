# Ampliq — Company Website

Bilingual (Arabic / English) multi-page website for **Ampliq** — *Amplify Your Business Impact*.

- Content: *Ampliq Company Profile 2026*
- Visual identity: *Ampliq Design System v1.0* (navy · gold · silver, IBM Plex Sans Arabic + Montserrat)
- Requirements and acceptance criteria: the NOB website analysis (page templates, SEO, performance, RTL, accessibility)

Arabic is the default language at the site root (right-to-left); English lives under `/en/`. Every page is static HTML generated by a small Node script, so it is fast, fully crawlable, and hostable anywhere. Content is edited from a dashboard at `/admin/` (Decap CMS) — see **[DASHBOARD.md](DASHBOARD.md)** (Arabic guide).

## Quick start

```bash
npm install      # once (installs the Markdown renderer)
npm run dev      # build + preview at http://localhost:4173
npm run build    # rebuild dist/ after editing anything in src/
```

Requires Node 20+.

To use the dashboard locally without logging in, run `npx decap-server` in the project folder alongside `npm run dev`, then open http://localhost:4173/admin/. Edits are written straight to `src/content/`.

## Before going live

Fill in **Settings → بيانات التواصل والربط** in the dashboard (stored in `src/content/settings.json`):

| Setting | What it does |
|---|---|
| `siteUrl` | e.g. `https://ampliq.sa` (on Netlify it defaults to the site's main URL). Adds canonical + hreflang tags, absolute share-image URLs, breadcrumb structured data, and `sitemap.xml` / `sitemap-ar.xml` / `sitemap-en.xml` with `lastmod`. Can also be set at build time with `SITE_URL=https://… npm run build`. |
| `contact.email`, `contact.phone` | Shown on the contact page, home page and footer as working links. Until set, bracketed placeholders are shown. |
| `contact.whatsapp` | Digits only, e.g. `9665XXXXXXXX`. Turns on the floating WhatsApp button (its message names the current page). |
| `formEndpoint` | Where the contact form posts (JSON `POST`, any 2xx = success) — e.g. Formspree, Getform or your own API. Without it, the form opens the visitor's email app addressed to `contact.email`; with neither, it says the form isn't connected yet. |
| `gtmId` | Google Tag Manager container. GTM loads on every page with Consent Mode v2: analytics storage stays denied (no analytics cookies) until the visitor accepts in the cookie banner; advertising storage is never granted. The site pushes `generate_lead` (form sent), `click_phone` / `click_email` / `click_whatsapp`, `language_switch` and `view_service` events to `dataLayer` — never what a visitor typed. |

Also review before launch:

- **Legal pages** (dashboard → صفحات الموقع → سياسة الخصوصية / شروط الاستخدام) are drafts aligned with Saudi Arabia's PDPL — have them reviewed by your legal adviser.
- **Client logo names**: the dark-green logo (`green`) has a generic alt text; add its name in dashboard → الإعدادات → شعارات العملاء.
- **Blog articles** are written from the company profile; review them before publishing.

## Editing content

Everything is editable from the dashboard. Behind it, each item is a JSON file holding both languages as `{ "ar": {…}, "en": {…} }`:

| File | Contents | Dashboard section |
|---|---|---|
| `src/content/blog/*.json` | One file per article; the body is Markdown. The file name is the URL slug. | المدونة |
| `src/content/services/*.json` | One file per service page, including its FAQ | الخدمات |
| `src/content/pages/*.json` | Home, about, services, clients, blog, contact, privacy, terms | صفحات الموقع |
| `src/content/shared.json` | Sections reused across pages (numbers, approach, why us, sectors…) | النصوص المشتركة |
| `src/content/general.json` | Navigation, footer, form labels and messages, interface text | النصوص المشتركة |
| `src/content/settings.json`, `clients.json` | Contact details, site URL, form endpoint, GTM; client logos | الإعدادات |

Uploaded images go to `src/assets/uploads/` (client logos and team photos to their own folders).

The build is forgiving about content: an English text left empty falls back to the Arabic one (with a warning), an article without an English title and body is published in Arabic only, and Persian look-alike letters (ی ک) are replaced with Arabic ones. It stops with a clear message if a page doesn't have exactly one `<h1>`, or an article misses its Arabic title or body.

## Project structure

```
build.mjs                 # generates dist/ from src/ (and dist/admin/config.yml)
netlify.toml              # Netlify build settings, security and cache headers
scripts/serve.mjs         # local preview server
scripts/check.mjs         # SEO / link / schema checks on dist/ (npm test)
scripts/og.mjs            # optional: regenerates the per-page share images (needs Playwright)
src/
  content/                # all text and settings as JSON (edited from the dashboard)
  content.mjs             # loads the JSON, renders Markdown, last-modified dates from git
  seo.mjs                 # head metadata and site-wide structured data
  admin/                  # dashboard: page, Arabic interface, config generator
  templates/layout.mjs    # <head>, header, footer, widgets
  templates/components.mjs# reusable sections (cards, steps, FAQ, form, …)
  templates/pages.mjs     # one renderer per page template + structured data
  lib.mjs, icons.mjs      # helpers and icon set
  styles/main.css         # design-system tokens and all styles
  scripts/main.js         # menu, rotator, blog filter, form, consent, events
  assets/                 # fonts, logos, client logos, favicons, share images
dist/                     # built site — deploy this folder (not committed)
```

## SEO and quality built in

SEO logic lives in `src/seo.mjs` (head tags, Organization/WebSite schema). Full audit and change log: **[docs/SEO-REPORT.md](docs/SEO-REPORT.md)** (Arabic).


- A hand-written title and description per page, in the page's language, and a share image per page (`src/assets/og/`).
- One `<h1>` per page; short Latin URLs for both languages.
- Structured data: one `Organization` + `WebSite` with fixed `@id`s on every page; `ProfessionalService` (home), `Service` + `FAQPage` (service pages), `BlogPosting` (articles, with optional author), `BreadcrumbList` (when `siteUrl` is set).
- `robots.txt` names Googlebot, Bingbot, OAI-SearchBot, ChatGPT-User, PerplexityBot and Claude-SearchBot explicitly; `llms.txt` lists the published pages. Sitemap `lastmod` comes from the git history of each page's content files, so rebuilding doesn't change it.
- Any page, service or article can be hidden from search engines from the dashboard (noindex + left out of the sitemap and `llms.txt`).
- All numbers and text are in the HTML; JavaScript only adds enhancements (rotator, filters, form handling).
- Self-hosted fonts with `font-display: swap`; WebP images; lazy loading below the fold; pages weigh roughly 400–650 KB.
- Respects reduced-motion settings (the logo marquee, rotator and hero animation stop).
- Keyboard navigation, visible focus, labelled form fields with inline errors, and WCAG AA colour pairs from the design system.

## Checks

```bash
npm test   # builds with SITE_URL=https://ampliq.netlify.app, then checks dist/
```

`scripts/check.mjs` fails on broken internal links, missing/duplicate canonical, non-reciprocal hreflang, sitemap entries that aren't indexable pages, invalid JSON-LD, a wrong `lang`/`dir`, or anything that looks like a secret key; it warns on duplicate or over-long titles and descriptions.

## Share images

`src/assets/og/{ar,en}/*.jpg` are generated from the page titles. New articles use their cover image (or the home image) until you regenerate them. After adding a page or changing a title:

```bash
npx playwright install chromium   # once
npm run og
```

## Deploying

`dist/` is a complete static site:

- **Netlify (recommended — the dashboard logs in through it):** settings are in `netlify.toml`. Every save in the dashboard commits to GitHub and Netlify republishes the site within a minute or two. Setup steps: [DASHBOARD.md](DASHBOARD.md).
- **Other hosts:** build command `npm run build`, publish directory `dist`, `SITE_URL` set to the live domain. The dashboard then needs its own GitHub login service (see Decap CMS docs, "External OAuth clients").

`dist/404.html` is served by most static hosts for unknown URLs.
