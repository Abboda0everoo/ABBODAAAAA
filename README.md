# Ampliq — Company Website

Bilingual (Arabic / English) multi-page website for **Ampliq** — *Amplify Your Business Impact*.

- Content: *Ampliq Company Profile 2026*
- Visual identity: *Ampliq Design System v1.0* (navy · gold · silver, IBM Plex Sans Arabic + Montserrat)
- Requirements and acceptance criteria: the NOB website analysis (page templates, SEO, performance, RTL, accessibility)

Arabic is the default language at the site root (right-to-left); English lives under `/en/`. Every page is static HTML generated by a zero-dependency Node script, so it is fast, fully crawlable, and hostable anywhere.

## Quick start

```bash
npm run dev      # build + preview at http://localhost:4173
npm run build    # rebuild dist/ after editing anything in src/
```

Requires Node 18+. No `npm install` needed.

## Before going live

Fill in `src/config.mjs`:

| Setting | What it does |
|---|---|
| `siteUrl` | e.g. `https://ampliq.sa`. Adds canonical + hreflang tags, absolute share-image URLs, breadcrumb structured data, and `sitemap.xml` / `sitemap-ar.xml` / `sitemap-en.xml` with `lastmod`. Can also be set at build time with `SITE_URL=https://… npm run build`. |
| `contact.email`, `contact.phone` | Shown on the contact page, home page and footer as working links. Until set, bracketed placeholders are shown. |
| `contact.whatsapp` | Digits only, e.g. `9665XXXXXXXX`. Turns on the floating WhatsApp button (its message names the current page). |
| `form.endpoint` | Where the contact form posts (JSON `POST`, any 2xx = success) — e.g. Formspree, Getform or your own API. Without it, the form opens the visitor's email app addressed to `contact.email`; with neither, it says the form isn't connected yet. |
| `gtmId` | Google Tag Manager container. Shows a cookie-consent banner and loads GTM only after the visitor accepts. The site pushes `generate_lead` (form sent) and `contact_click` (phone / email / WhatsApp) events to `dataLayer`. |

Also review before launch:

- **Legal pages** (`pages.privacy` / `pages.terms` in the content files) are drafts aligned with Saudi Arabia's PDPL — have them reviewed by your legal adviser.
- **Client logo names**: the dark-green logo (`green`) has a generic alt text; add its name in `src/config.mjs`.
- **Blog articles** are written from the company profile; review them before publishing.

## Editing content

| File | Contents |
|---|---|
| `src/content/ar.mjs` | All Arabic text: navigation, pages, services, FAQ, form, legal |
| `src/content/en.mjs` | All English text — same structure as Arabic |
| `src/content/blog/*.mjs` | One file per article, both languages inside. Add a file to publish a new article. |
| `src/config.mjs` | Contact details, site URL, form endpoint, GTM, client logos |

The build stops with a clear message if:

- the Arabic and English files fall out of step (a missing key or a different number of items),
- a page doesn't have exactly one `<h1>`,
- Arabic text contains Persian letters (پ چ ژ گ ک ی).

## Project structure

```
build.mjs                 # generates dist/ from src/
scripts/serve.mjs         # local preview server
scripts/og.mjs            # optional: regenerates the per-page share images (needs Playwright)
src/
  config.mjs              # site settings and client list
  content/ar.mjs, en.mjs  # all page text
  content/blog/           # articles
  templates/layout.mjs    # <head>, header, footer, widgets
  templates/components.mjs# reusable sections (cards, steps, FAQ, form, …)
  templates/pages.mjs     # one renderer per page template + structured data
  lib.mjs, icons.mjs      # helpers and icon set
  styles/main.css         # design-system tokens and all styles
  scripts/main.js         # menu, rotator, blog filter, form, consent, events
  assets/                 # fonts, logos, client logos, favicons, share images
dist/                     # built site — deploy this folder
```

## SEO and quality built in

- A hand-written title and description per page, in the page's language, and a share image per page (`src/assets/og/`).
- One `<h1>` per page; short Latin URLs for both languages.
- Structured data: `Organization` + `ProfessionalService` (home), `Service` + `FAQPage` (service pages), `Article` (articles), `BreadcrumbList` (when `siteUrl` is set).
- All numbers and text are in the HTML; JavaScript only adds enhancements (rotator, filters, form handling).
- Self-hosted fonts with `font-display: swap`; WebP images; lazy loading below the fold; pages weigh roughly 400–650 KB.
- Respects reduced-motion settings (the logo marquee, rotator and hero animation stop).
- Keyboard navigation, visible focus, labelled form fields with inline errors, and WCAG AA colour pairs from the design system.

## Share images

`src/assets/og/{ar,en}/*.jpg` are generated from the page titles. After changing a title, regenerate them:

```bash
npx playwright install chromium   # once
npm run og
```

## Deploying

`dist/` is a complete static site:

- **Netlify / Vercel / Cloudflare Pages:** build command `npm run build`, publish directory `dist`, environment variable `SITE_URL` set to the live domain.
- **GitHub Pages / any web server:** upload the contents of `dist/`.

`dist/404.html` is served by most static hosts for unknown URLs.
